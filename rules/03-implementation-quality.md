# Implementation Quality

Общие принципы качества кода (focused functions, минимум комментариев, обновление тестов при изменении поведения) уже в системном промпте. Здесь только то, что специфично для рабочего стека.

- Не смешивай функциональные правки и стилистический рефакторинг в одном коммите — это усложняет ревью и rollback.
  Исключение: приведение тронутого метода к java-конвенции (rule 05) — это часть самой правки, а не отдельный рефакторинг.
- Поведение, которое реально пошло в staging/prod, нельзя «починить» через rewrite истории — только новый коммит.
- Для Java/Spring изменений, затрагивающих транзакции, JPA-маппинг или Kafka — план обязателен, даже если правка кажется маленькой.
