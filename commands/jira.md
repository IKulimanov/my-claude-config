# Jira — задача для человека

Формат и правила — `~/dev/my-claude-config/playbook/templates/task-template.md` (прочитать перед генерацией).
Процесс — плейбук `~/dev/my-claude-config/playbook/projects-playbook.md`, чек-листы по типам работ — `playbook/task-writing.md` («Рекомендации по
описанию задач»). Задача пишется для разработчика: он придёт с «а точно так?», а не «а как?».

## Шаги

1. Тип: подзадача (по умолчанию) | дев-задача (родитель этапа) | баг | спайк. Если неясно — один вопрос.
2. Контекст: локальный `CLAUDE.md` (домен, ограничения) и, если пользователь дал ссылку/файл design или ADR, —
   прочитать нужный раздел, чтобы ссылаться, а не пересказывать.
3. Если в промте уже есть черновик — сохранить формулировки автора, править только структуру и
   проверяемость критериев. Не «улучшать» смысл.
4. Сгенерировать текст в Jira-разметке по шаблону ниже. Русский. Заголовок — «Глагол + объект».
5. Проверить по чек-листу; вывести текст одним блоком, без комментариев вокруг.

## Подзадача (основной случай)

```
h3. <Глагол + объект>

*Дизайн:* <ссылка на раздел / ADR — только если суть задачи там определена>
*Что сделать:* <2–4 предложения с бизнес-правилами, без имён классов/DDL/колонок>

*Критерии приёмки:*
* Дано <состояние>, когда <действие>, тогда <наблюдаемый результат>.
* Дано <…>, когда <…>, тогда <…>.
* Дано <ошибочное условие>, когда <…>, тогда <ошибка / статус / поведение>.

*Открытые вопросы:*
* <вопрос> — <владелец>          (блок убрать, если вопросов нет)

*Не входит:* <…>
*Зависимости:* <задачи, контракты>   (убрать, если нет)
*Оценка:* <ч>
```

## Дев-задача (родитель)

```
h3. [<проект>] Этап N. <название>
*Зачем:* <1–2 предложения>
*Результат этапа:* <что можно показать/пощупать>
*Состав:* <список подзадач одной строкой каждая>
*Открытые вопросы:* <сводка из подзадач, с владельцами>
*Зависимости:* <…>
```

## Баг

```
h3. <Что не работает — глагол + объект>
*Наблюдаемое:* <что происходит>. *Ожидаемое:* <что должно>.
*Воспроизведение:* # шаг # шаг # результат
*Влияние:* <кто и как часто страдает>
*Гипотеза причины:* <если есть; иначе «неизвестна»>
*Критерии приёмки:* Дано <…>, когда <…>, тогда <…> (сценарий, который сейчас падает).
```

## Спайк

```
h3. Исследовать <вопрос>
*Решение, которое надо принять:* <…>
*Лимит времени:* <ч/дн>
*Результат:* <ADR / сравнительная таблица / PoC в ветке>
```

## Чек-лист перед выдачей

- каждый критерий — Дано/Когда/Тогда, проверяем наблюдаемым результатом; есть сценарий ошибки; ≤5 сценариев
- нет имён классов, DDL, колонок; нет типового DoD («ревью, тесты, Sonar») — только нестандартное
- нет ИИ-фраз («важно отметить», «данный функционал», «обеспечить корректную работу»), нет эмодзи
- открытые вопросы — только настоящие, с владельцем
- размер подзадачи 4–10 ч; больше — предложить разбить, но не разбивать молча
