# /task — оркестратор больших задач

Два этапа. Подготовка — один раз на задачу: контекст, план всей задачи с вехами, критика, согласование.
Реализация — по этому плану, без нового анализа и нового плана; перепланирование только по триггеру.

Главный поток тонкий: держит статусы и короткие отчёты. Не читает целиком план, кейсы и код — статус
даёт `plan-status.sh <plan.md> --summary`. Агенты сами пишут свои файлы и возвращают не больше 10 строк.
`general-purpose` и `Explore` здесь не используются: контекст — `scout`, код — `implementer`.

Аргументы: `$ARGUMENTS` = "$ARGUMENTS". Пусто — спроси, что делать.

## Этап 1 — подготовка

### Шаг 0 — Сортировка и вопросы

Определи по тексту, что это, и не запускай лишнего:
- вопрос, анализ, объяснение без изменения кода → ответь сам и остановись;
- правка в одно предложение без изменения поведения → «это /quick»;
- баг или малое изменение поведения → «это /fix»;
- фича в один контекст (одна фаза, не больше 8 правок файлов) → «это /feature»;
- иначе — дальше. Сомневаешься между `/feature` и `/task` — бери `/feature`.

Стек и профиль — `~/.claude/my-claude-config/shared/stack-detection.md`. Вопросы в начале задачи — оттуда же,
одним AskUserQuestion: в personal — тесты и коммиты; в любом профиле — вариант автора (правило 08), если его
нет в постановке. «Продолжай» — без вопросов. Запомни время старта.

### Шаг 1 — Каталог задачи

```bash
DIR=$(~/.claude/my-claude-config/scripts/helpers/ai-init.sh)   # .claude/tasks/<ключ>/ — последний каталог ветки
```

- Нет `plan.md` — новая задача, дальше по шагам.
- Есть `plan.md`, нет `summary.md` — «продолжай»: `plan-status.sh $DIR/plan.md --summary` и реализация
  со следующего шага. Контекст, план и согласование заново не делаются.
- Есть `summary.md` — доработка с новыми требованиями: `PREV=$DIR`, `DIR=$(ai-init.sh --new)`.

Файлы: для человека — `plan.md`, `tests.md` (режим `tdd`), `review.md`, `summary.md`; для агентов —
`agent/context.md`, `agent/scope.txt`, `agent/critique.md`, `agent/review-<агент>-<веха>.md`, `agent/sonar.md`.
Слепок репозитория — `.claude/tasks/about.md`. Ничего из каталога не удаляй.

### Шаг 2 — Контекст (`scout`, один раз)

Только если нет `$DIR/agent/context.md`. Промпт: каталог задачи, постановка дословно, вариант автора, пути
к документам `docs/projects/`, если есть. Доработка — режим «дельта» с `$PREV/summary.md` и `$PREV/plan.md`.

### Шаг 3 — План (`planner`, режим «план»)

Промпт: каталог задачи, ответы из шага 0 (`Тесты:`, `Коммиты:`), вариант автора, `docs/projects/<проект>/`
(brief, design, `02-plan.md`), если есть. Выход за один запуск: `plan.md` со всеми вехами, кейсы по режиму
тестов, `agent/scope.txt`. Проверь по `--summary`: шапка на месте, у шагов статусы `[ ]`. Не так — перезапусти
планировщика с точным замечанием.

### Шаг 4 — Критика (`critic`, один раз)

Промпт: каталог задачи. Выход `agent/critique.md`. Есть «блокирует» или «стоит» — `planner` в режиме «правка
плана» по критике; иначе сразу к согласованию.

### Шаг 5 — Согласование (единственная остановка)

Покажи в чат: «Решение», вехи с «готово, когда», число шагов и кейсов, замечания критика по строке.
AskUserQuestion: «Согласовать план?» — «да», «поправить: …», «стоп-точки на шаги …». Стоп-точка —
`plan-status.sh <plan.md> <шаг> stop`; правки — через `planner`. В work автор добавляет хотя бы один свой
кейс или говорит «случаи твои» (правило 06). После «да» — `Статус: согласован <дата>`.

## Этап 2 — реализация

### Шаг 6 — Фазы всех вех подряд

Для каждой фазы по порядку, без нового контекста и плана:
1. Режим `tdd` — стек-тест-райтер (`test-writer` / `go-test-writer` / `vue-test-writer`): кейсы фазы из
   `tests.md`, пути из плана; сам пишет файлы тестов и подтверждает RED.
2. `implementer`: пути к `plan.md`, `agent/scope.txt`, `agent/context.md` (и `tests.md`), номер фазы, стек,
   команда тестов. Режим тестов и коммиты он берёт из шапки плана.
3. После агента — `plan-status.sh $DIR/plan.md --summary`:
   - `[!]` — доложи вопрос. Меняет поведение, контракт или scope — `planner` в режиме «правка плана» по вопросу
     и `git diff`, правится только затронутая веха. Нужен файл вне scope — подтверждение пользователя,
     `scope.sh $DIR add <путь>`, фаза заново;
   - `[#]` — доложи и жди «дальше», затем `plan-status.sh <шаг> todo`;
   - иначе — следующая фаза. В чат — одна строка: фаза, тесты, коммит.

### Шаг 7 — Проверка вехи

Тесты проекта целиком через `scripts/helpers/test-summary.sh` (режим `нет` — сборка). Рабочий Java-проект
при заданных `SONAR_HOST_URL` и `SONAR_TOKEN`: `scripts/helpers/sonar-local.sh` → `$DIR/agent/sonar.md`;
собственные правила и BLOCKER/HIGH — исправить, MEDIUM механические — исправить, спорные — один вопрос
пакетом; не больше двух кругов.

### Шаг 8 — Ревью вехи

Параллельно: work — `convention-reviewer` (дифф вехи + `agent/sonar.md`) и стек-ревьюер (`java-reviewer` /
`go-reviewer` / `vue-reviewer`); personal — только стек-ревьюер; при миграциях, индексах, JPA-маппинге ещё
`migration-reviewer`. Каждому — дифф вехи, `plan.md` и путь его файла `agent/review-<агент>-<веха>.md`.
Есть CRITICAL или WARNING — фиксер: `implementer` в режиме «правки по ревью», он же пишет `review.md`.
Повторное ревью — один раз и только при CRITICAL или правках логики больше чем в трёх файлах.

### Шаг 9 — Граница вехи

Строка в журнал плана: веха готова, тесты, ревью. Следующая веха — сразу, без остановки. Перед перерывом
дольше часа посоветуй `/clear` и `/task продолжай`: план и статусы на диске, а длинный контекст после паузы
целиком перезаписывается в кэш.

### Шаг 10 — Итог

`scope.sh $DIR done`. `$DIR/summary.md` по `~/.claude/my-claude-config/playbook/templates/summary-template.md`
(тесты, Sonar, ревью, время от старта - в свёрнутых блоках). В чат: раздел "Итог", что проверить руками, вопросы
к пользователю и путь к файлу, без пересказа остального.

## Ошибки

- Агент завис или не дописал файл — перезапусти шаг свежим агентом с более точной инструкцией.
- В режиме `tdd` не получается написать падающий тест первым — пауза и вопрос (правило 06).
- Хвосты после завершения: мелочь — `/quick` или `/fix`; недоделанный кусок — `/task <описание>` на той же ветке.
