# ADR — записать решение

Правила и формат — `~/.claude/my-claude-config/playbook/templates/adr-template.md` (прочитать перед работой).
Rule 08: если пользователь просит «предложи решение», а не «запиши решение» — сначала его вариант.

## Шаги

1. Найти шаблон репозитория: `docs/adr/0000-adr-template.md`, `adr/000*-template.md`, `docs/adr/README.md`.
   Есть — структура берётся из него дословно; нет — из shared-шаблона. Нумерация — следующая за максимальной
   в каталоге; имя файла `NNNN-<kebab-решение>.md` в стиле соседних.
2. Собрать факты: контекст (что упирается), реальные варианты с именами, выбранное решение, инварианты,
   минусы. Чего не хватает — **один** вопрос через AskUserQuestion, не список.
3. Написать ADR. Объём 40–70 строк. Русский; английское — только термины без русского эквивалента.
4. Прогнать чек-лист из шаблона: заголовок = решение («X, а не Y»), ≥2 варианта с причиной отклонения,
   отрицательные последствия есть, ни одной запрещённой фразы, все имена конкретные, ничего лишнего
   (логгеры, версии, стиль кода — вон).
5. Показать текст, спросить, сохранять ли (путь назвать). Сохранить только после «да».
   Статус: «Принят» только если пользователь так сказал; иначе «Предложен».

## Режим чистки (`$ARGUMENTS` — путь к ADR)

Прочитать файл. Убрать: ИИ-фразы, пересказ контекста в других секциях, детали, не влияющие на решение,
эмодзи/декор, английские слова с русским эквивалентом. Не менять смысл решения и не «улучшать» варианты
без запроса. Показать дифф (кратко: что удалено и почему), применить после подтверждения.

## Чего не делать

- Не писать design doc внутри ADR (схемы, контракты, NFR — в `01-design.md`).
- Не переписывать принятый ADR — новый ADR со ссылкой «Заменяет ADR-NNNN».
- Не добавлять секции «Итог», «Заключение», «Рекомендации».
