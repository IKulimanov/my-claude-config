# Feature Development

Команда для любой новой фичи или заметного изменения. Она требует сначала план, а потом код, и сама
грузит скилы под определённый стек.

## Порядок работы

### Шаги 1-2 — Загрузить контекст, определить стек, загрузить скилы

Следуй общему блоку `~/.claude/my-claude-config/docs/shared/stack-detection.md`. В нём: чтение
локального `CLAUDE.md`, детект Java/Spring · Go · Vue/Vite · Web, определение профиля work или
personal, переформулировка требования и таблицы загрузки скилов по стекам.

### Шаг 3 — Разметить затронутые слои

Перечисли все слои, которых коснётся фича, по чек-листу
`~/.claude/my-claude-config/docs/shared/affected-layers.md` (Java/Spring · Go · Vue/Vite).

### Шаг 4 — Назвать открытые вопросы

Вытащи неоднозначности, из-за которых реализация выйдет неправильной:
- пропущенные требования (краевые случаи, поведение при ошибке, правила валидации);
- решения с реальными компромиссами;
- внешние зависимости, которые надо согласовать (изменение схемы, контракт API);
- риски выката (обратная совместимость, миграция данных);
- вопросы безопасности.

**Не спрашивай про очевидное. Только настоящие блокеры.**

### Шаг 5 — Составить поэтапный план реализации

Покажи план на подтверждение до реализации, в общем формате
`~/.claude/my-claude-config/docs/shared/plan-template.md` — секции на русском, включая **обязательную
«Каким путём идём»** (объясняет выбранный подход и почему именно он, а не просто перечисляет шаги).
По плану читатель должен пройти за твоей мыслью, а не только увидеть список изменений.

**Дождись подтверждения или ответов на открытые вопросы.**

#### Сохранить план в `.ai/` (лёгкая конвенция)

Если работаешь внутри репозитория, сохрани утверждённый план как долгоживущий артефакт — он переживёт
сжатие контекста и доработки. См. `docs/AI_ARTIFACTS.md`.

```bash
DIR=$(~/.claude/my-claude-config/scripts/helpers/ai-init.sh "<feature>")   # создаст .ai/<feature>/, заигнорит .ai/
```

Запиши план в `$DIR/plan.md`. Обновляй его по ходу реализации. Для тривиальных изменений можно не сохранять.

### Шаг 6 — Реализовывать шаг за шагом (сначала тест, железное правило)

После подтверждения на каждом шаге:
1. **RED:** падающий тест пишется ПЕРВЫМ. Дизайн теста делегируй профильному агенту: Java/Spring → `test-writer`, Go → `go-test-writer`, Vue/Vite → `vue-test-writer`. Агент read-only: он возвращает код теста; ты записываешь его в файл теста и запускаешь, убедившись, что он падает по правильной причине. Для остальных стеков пиши падающий тест напрямую. (Либо тест пишет пользователь — про авторство тестов см. `rules/06-tdd-discipline.md`.)
2. **GREEN:** напиши минимальный прод-код, чтобы тест прошёл. Запусти. Убедись, что зелёный.
3. **REFACTOR:** почисти код и тест без смены поведения. Перезапусти тесты.
4. Только ПОСЛЕ этого переходи к следующему шагу.

Если падающий тест написать нельзя (например, действительно чисто визуальное изменение без поведения, которое можно проверить) — остановись и обсуди, прежде чем продолжать. См. `rules/06-tdd-discipline.md`.

Если всплыла неожиданная сложность — остановись и доложи, прежде чем продолжать.

### Шаг 7 — Проверить

Запусти подходящую проверку:
- **Java**: `mvn verify` (или команду из `CLAUDE.md`)
- **Go**: `go test ./... && go vet ./...`
- **Vue/Vite**: `npm run test` или `npx vitest run`

### Шаг 8 — Ворота конвенции (рабочие Java-проекты), затем отчёт

Прежде чем объявить фичу готовой, прогони предчек конвенции по итоговому диффу — отклонения должны
находиться локально, а не в CI. В профиле **work** для Java (rule «Профили проектов») сверь дифф с
Sonar-aligned чек-листом `~/.claude/my-claude-config/skills/java-service-convention/references/sonar-rules.md`
(коды LANG-/SPR-/DB-) — это то же самое, что запустить `/convention-check`. Нарушения чини по TDD,
потом перепроверь. Это предфильтр: окончательные ворота — CI Sonar (`mvn verify sonar:sonar
-Dsonar.qualitygate.wait=true`). Для не-Java и личных проектов шаг пропускается.

`sonar-rules.md` — внутренний материал команды: цитируй коды правил (LANG-410, SPR-902), не вставляй
его текст и примеры кода дословно в общедоступные выводы.

Только после этого — доложи, что проверено, каков результат ворот конвенции и какие остались риски.
