# /feature - фича в один контекст

## Шаг 1 - Контекст и стек

`~/.claude/my-claude-config/shared/stack-detection.md`: локальный `CLAUDE.md`, стек, рабочий или личный
проект, нужные скилы, вопросы в начале задачи (в personal - тесты и коммиты, одним вызовом вместе с
вариантом автора). Переформулируй требование в конкретных технических терминах.

## Шаг 2 - Слои и вопросы

Перечисли затронутые слои по `~/.claude/my-claude-config/shared/affected-layers.md`. Вопросы - только
настоящие блокеры: нехватка требований, развилка с важным выбором, внешняя зависимость, риск выката,
безопасность. Вариант автора (правило 08) спрашивается в шаге 1 вместе с остальными вопросами.

## Шаг 3 - План, кейсы и scope

Загрузи скил `planning`. Напиши план по `~/.claude/my-claude-config/playbook/templates/plan-template.md`
с шапкой `Тесты:` и `Коммиты:`; кейсы - в секции "Тесты" плана в формате Дано/Когда/Тогда с уровнем,
объём по режиму: `tdd` - до трёх на шаг с поведением, `ключевые` - до двух на шаг с логикой, `нет` - без кейсов. Требования - только из постановки и кода; чего там нет - в "Вопросы", а не в допущения.
Каталог задачи текущей ветки (`.claude/tasks/<ключ>/`; есть `summary.md` прошлой задачи - `--new`):

```bash
DIR=$(~/.claude/my-claude-config/scripts/helpers/ai-init.sh)
```

Сохрани план в `$DIR/plan.md`; файлы всех шагов и каталоги тестов - в scope:
`scripts/helpers/scope.sh $DIR add <путь>...` (маска `*` захватывает подкаталоги, `/` на конце - каталог).

## Шаг 4 - Критик

`critic`, один проход, вход - план с кейсами; выход `$DIR/agent/critique.md`. Внеси "блокирует" и "стоит",
"по желанию" - в "Границы"; `scope.txt` обновить, если список файлов изменился.

## Шаг 5 - Согласование (единственная остановка)

Покажи "Решение", шаги и кейсы. AskUserQuestion: "Согласовать план и кейсы?" - "да", "поправить: ...",
"добавить кейсы: ...". В work автор добавляет хотя бы один свой случай или говорит "случаи твои"
(правило 06). После "да" - `Статус: согласован <дата>` в плане; в work кейсы заморожены.

## Шаг 6 - Реализация по шагам (режим из шапки `Тесты:`)

Для каждого шага: `plan-status.sh <plan.md> <шаг> wip` ->
1. **RED:** `tdd` - стек-тест-райтер (`test-writer` / `go-test-writer` / `vue-test-writer`) сам пишет файлы
   тестов по кейсам шага и подтверждает падение (или пользователь, если он взял тесты на себя);
   `ключевые` - тест для шага с кейсом пишешь сам; `нет` - шаг без теста, проверка сборкой или запуском.
2. **GREEN:** минимальный прод-код, тесты зелёные.
3. **REFACTOR:** почисти без смены поведения, тесты снова зелёные.
`plan-status.sh <шаг> done`. В work кейсы после согласования не менять - нужное изменение через вопрос.
Понадобился файл вне `scope.txt` - сначала вопрос пользователю, после "да" `scope.sh $DIR add <путь>`.
Стоп-точка `[#]` - остановись и жди "дальше".

## Шаг 7 - Проверка и Sonar

Полный прогон тестов через `test-summary.sh`. Рабочий Java-проект при заданных `SONAR_HOST_URL`
и `SONAR_TOKEN`: `scripts/helpers/sonar-local.sh` -> `$DIR/agent/sonar.md`, цикл исправлений как в `/task`
шаг 10 (собственные правила и BLOCKER/HIGH - чинить; спорные - один вопрос пакетом; не больше двух кругов).

## Шаг 8 - Ревью

Work - параллельно `convention-reviewer` и стек-ревьюер (`java-reviewer` / `go-reviewer` / `vue-reviewer`);
personal - только стек-ревьюер; при миграциях ещё `migration-reviewer`. Каждому - путь его файла
`$DIR/agent/review-<агент>.md`. Закрой CRITICAL и WARNING по режиму тестов; повторное ревью - один раз
и только при CRITICAL. Итог - в `$DIR/review.md`: находки по серьёзности с пометкой "закрыто", "осталось" или
"отклонено: причина".

## Шаг 9 - Отчёт

`scope.sh $DIR done`. `$DIR/summary.md` по `~/.claude/my-claude-config/playbook/templates/summary-template.md`
(проверки, Sonar, находки ревью, остаточные риски - в свёрнутых блоках). В чат: раздел "Итог", что проверить
руками, вопросы и путь к файлу. Коммит - только по просьбе и только в локальную ветку (правило 09).
