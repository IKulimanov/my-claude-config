# Архитектура конфигурации Claude Code

## Диаграмма взаимосвязей

```
┌─────────────────────────────────────────────────────────────────┐
│                     СЕССИЯ CLAUDE CODE                           │
│                                                                  │
│  ┌──────────────────┐  Загружаются ВСЕГДА при старте сессии      │
│  │  CLAUDE.md        │  (полностью, без лимита, рек. <200 строк) │
│  │  rules/           │  (полностью, держать короткими)           │
│  │  MEMORY.md        │  (первые 200 строк)                       │
│  │  Описания skills  │  (~8K chars суммарно)                     │
│  └──────┬───────────┘                                            │
│         │                                                        │
│  Пользователь вводит: /review                                    │
│         │                                                        │
│  ┌──────▼───────┐     ┌──────────────┐    ┌───────────────┐     │
│  │  SKILL /     │────>│   AGENT      │───>│  SKILLS       │     │
│  │  COMMAND     │     │  (subagent)  │    │  (preloaded)  │     │
│  │  review.md   │     │  java-       │    │  java-svc-    │     │
│  │              │     │  reviewer.md │    │  convention   │     │
│  │  Маршрути-   │     │             │    │  jpa-db       │     │
│  │  зирует к    │     │  model:     │    │  testing      │     │
│  │  нужному     │     │   sonnet    │    │  integration  │     │
│  │  агенту      │     │  tools:     │    │              │     │
│  │              │     │   Read,...  │    │  paths:       │     │
│  └──────────────┘     └──────┬──────┘    │  **/*.java    │     │
│                              │           └───────────────┘     │
│  ┌───────────────────────────▼──────────────────────────┐      │
│  │                    HOOKS                              │      │
│  │  PreToolUse → проверяет ПЕРЕД выполнением             │      │
│  │  PostToolUse → проверяет ПОСЛЕ выполнения             │      │
│  │  exit 0 = разрешить, exit 2 = ЗАБЛОКИРОВАТЬ           │      │
│  └──────────────────────────────────────────────────────┘      │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  TEMPLATES (вне сессии)                                          │
│  Шаблоны для /onboard → генерируют CLAUDE.md при первом запуске  │
│  в новом проекте                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## Компоненты системы

### 1. CLAUDE.md — проектный контекст

**Что это:** Главный файл конкретного проекта. Загружается полностью при каждой сессии.

**Что туда писать:**
- Что делает сервис, какие у него границы
- Команды сборки/тестов (`mvn test`, `npm run dev`)
- Инварианты и ограничения
- Внешние зависимости (REST, Kafka, БД)
- Локальные исключения из общей конвенции

**Лимиты:**
- Рекомендуется < 200 строк (официальная рекомендация)
- Переживает compaction — перезагружается с диска
- Чем длиннее, тем хуже соблюдаются правила (~70% compliance)

### 2. Rules — универсальные правила

**Что это:** Короткие, стабильные правила, загружаемые ВСЕГДА.

```
rules/
  01-core-operating-model.md       ← "сначала читай CLAUDE.md, потом планируй"
  02-safety-and-scope.md           ← "не трогай чужие файлы, staging/master защищены"
  03-implementation-quality.md     ← "не мешай функциональные и стилевые правки"
  04-context-loading.md            ← "не загружай все skills сразу"
  05-convention-precedence.md      ← "локальный CLAUDE.md важнее глобальных правил"
  06-tdd-discipline.md             ← "жёсткое правило TDD + выбор авторства теста"
  07-communication-and-language.md ← "язык, тон, комментарии vs доки, ширина строки"
  08-think-first.md                ← "своя гипотеза до ответа агента"
  09-project-profiles.md           ← "work или personal: где командный процесс действует, а где нет"
```

**Как загружаются (важно):** Claude Code НЕ читает каталог `rules/` сам по себе. `setup-global.sh`
генерирует `~/.claude/CLAUDE.md` с блоком `@import` на каждый файл `rules/*.md` и на
`~/.claude/workspace.md` (каталоги work/personal этой машины). Так правила попадают в каждую сессию
через user-memory и наследуются субагентами (кроме встроенных Explore/Plan — они память пропускают).

**Принцип:** Если инструкция нужна ВСЕГДА и для ВСЕХ проектов — это rule. Если только для Java/Vue/Go — это skill.

### 3. Skills — модульные знания

**Что это:** Пакеты знаний, загружаемые по запросу.

```
skills/java-service-convention/
  SKILL.md              ← точка входа (описание + workflow + guardrails)
  references/
    java-style.md       ← глубокий reference
    spring-service.md
    kafka.md
```

**Как загружаются:**
1. При старте — только **описания** всех skills (~8K chars)
2. **Полный контент** загружается когда:
   - Ты вызываешь `/skill-name` вручную
   - Claude решает, что skill релевантен (по описанию)
   - Файл соответствует `paths:` паттерну в SKILL.md
3. После compaction — сохраняется первые 5,000 токенов на skill (бюджет 25K суммарно)

**Frontmatter поля:**
- `paths:` — автоактивация по паттерну файлов (`**/*.java`)
- `context: fork` — запуск в изолированном контексте
- `effort:` — уровень reasoning (low/medium/high/max)
- `model:` — override модели
- `disable-model-invocation: true` — только ручной вызов
- `allowed-tools:` — предодобренные инструменты

### 4. Commands → Skills (миграция)

**В новых версиях Claude Code commands и skills объединены.** Файл в `commands/review.md` и файл в `skills/review/SKILL.md` оба создают команду `/review`.

**Skills предпочтительнее** потому что поддерживают:
- Директорию с reference файлами
- Frontmatter для управления вызовом
- `paths:` для автоактивации
- `context: fork` для изоляции

### 5. Agents — изолированные субагенты

**Что это:** Отдельные контексты с собственной моделью, инструментами и знаниями.

```yaml
# agents/java-reviewer.md
name: java-reviewer
model: sonnet               # ← реальный override модели!
skills:                      # ← skills предзагружаются в агент
  - java-service-convention
  - testing
tools: ["Read", "Grep", "Glob", "Bash"]
```

Канонический frontmatter агента: `name`, `description`, `tools`, `model`, `skills`.
Поля `maxTurns` НЕ существует (см. CLAUDE.md «Конвенции авторинга»).

**Ключевые отличия от skills:**
- Skill загружается в **текущую** сессию (inline)
- Agent создаёт **отдельный изолированный контекст**
- У агента свой набор инструментов и модель
- Результат возвращается в основную сессию

### 6. Hooks — гарантированная защита

**CLAUDE.md и rules исполняются ~70% времени** (это LLM). Hooks — **детерминированный код**, исполняется ВСЕГДА.

**Exit codes:**
| Код | Значение |
|---|---|
| `exit 0` | Разрешить действие |
| `exit 2` | **ЗАБЛОКИРОВАТЬ** (stderr → feedback Claude) |
| Другой | Ошибка хука, действие разрешено |

**ВАЖНО:** `exit 1` — это НЕ блокировка!

**Типы хуков:**
| Тип | Что делает |
|---|---|
| `command` | Shell-скрипт, stdin=JSON контекст |
| `prompt` | Вопрос Haiku для yes/no решения |
| `agent` | Субагент для проверки (50 ходов, 60 сек) |
| `http` | POST на HTTP endpoint |

**Lifecycle events (основные):**
- `PreToolUse` — перед выполнением (можно заблокировать)
- `PostToolUse` — после выполнения (можно запустить линтер)
- `UserPromptSubmit` — перед обработкой промпта
- `SessionStart` — начало сессии
- `Stop` — Claude закончил ответ

### 7. Templates — начальная настройка

**Не часть runtime.** Шаблоны для команды `/onboard`:

```
/onboard       # в новом проекте — определяет стек, задаёт вопросы, пишет CLAUDE.md
```

Генерирует `CLAUDE.md` из нужного шаблона профиля (`java-service`, `go-service`, `vue-app` и др.).

## Модели: какую когда использовать

### Приоритет выбора модели

| Приоритет | Источник |
|---|---|
| 1 (высший) | `/model` команда в сессии |
| 2 | `--model` флаг при запуске CLI |
| 3 | Env variable `ANTHROPIC_DEFAULT_*_MODEL` |
| 4 | **`model:` в frontmatter агента** |
| 5 | Модель родительской сессии |
| 6 | Дефолт плана (Opus на Max, Sonnet на Pro) |

### Рекомендации по моделям

| Задача | Модель | Почему |
|---|---|---|
| Основная работа | Sonnet 4.6 | 90% задач, баланс цена/качество |
| Сложная архитектура | Opus 4.6 | Глубокое reasoning |
| Ревью кода | Sonnet 4.6 | Достаточно для анализа |
| Написание тестов | Sonnet 4.6 | Шаблонная работа |
| Простые правки | Haiku 4.5 | Быстро и дешево |
| Планирование | Opus 4.6 | Нужен глубокий анализ |

**`model: sonnet` в агентах — реальный override.** Если основная сессия на Opus, субагент всё равно работает на Sonnet.

## Поток токенов

```
Старт сессии (~5-6K tokens):
├── System prompt:          ~4,200 tokens
├── CLAUDE.md:              полностью (рекомендуем <200 строк)
├── rules/:                 полностью
├── MEMORY.md:              первые 200 строк
├── Описания skills:        ~8K chars суммарно
└── Env info:               ~280 tokens

Во время работы:
├── Вызванный skill:        без лимита
├── Субагент:               свой контекст, skills бюджет 25K
└── Инструменты:            результаты в контексте

После compaction:
├── CLAUDE.md:              перезагружается с диска (полностью!)
├── Skills:                 25K суммарно, 5K на каждый
└── MEMORY.md:              НЕ перезагружается
```

## Поток выполнения /review

```
Ты: /review
  │
  ▼
commands/review.md → загружается в контекст
  │
  ├─ Определяет стек (Java? Go? Vue?)
  │
  ├─ Java? → agents/java-reviewer.md
  │   ├─ Создаётся отдельный subagent
  │   ├─ model: sonnet
  │   ├─ Предзагружаются skills: [java-service-convention, testing, ...]
  │   ├─ Агент читает diff, анализирует, выдаёт findings
  │   └─ Результат → обратно в основную сессию
  │
  ├─ Vue? → agents/vue-reviewer.md
  │   ├─ model: sonnet
  │   ├─ skills: [vue-frontend]
  │   └─ ...
  │
  └─ Go? → agents/go-reviewer.md
      ├─ model: sonnet
      ├─ skills: [go-best-practices]
      └─ ...
```

## Связка компонентов

```
RULES (всегда загружены, универсальные)
  ↓ задают базовое поведение
SKILLS (загружаются по запросу, стек-специфичные)
  ↓ предоставляют знания
COMMANDS/SKILLS (повторяемые workflow)
  ↓ маршрутизируют к
AGENTS (изолированные роли с предзагруженными skills)
  ↓ защищаются
HOOKS (гарантированный enforcement)
  ↓ инициализируются через
TEMPLATES (начальная настройка проекта)
```
