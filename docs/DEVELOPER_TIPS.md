# Советы разработчикам по работе с Claude Code

## Выбор модели

| Задача | Модель | Почему |
|---|---|---|
| Основная разработка (90% задач) | **Sonnet 4.6** | Баланс цена/качество, достаточно для большинства задач |
| Сложная архитектура, планирование | **Opus 4.6** | Глубокое reasoning, trade-off анализ |
| Ревью кода, написание тестов | **Sonnet 4.6** | Достаточно для анализа и шаблонной работы |
| Простые правки, добавить поле | **Haiku 4.5** | Быстро и дешево |
| Миграции БД, критичные решения | **Opus 4.6** | Цена ошибки высока |

**Совет:** Используй `model: sonnet` в agents для рутинных задач. Opus только для `planner` и `migration-reviewer`.

## Промпт-инженерия для Claude Code

### 1. Давай критерии проверки (самый важный паттерн)

```
# Плохо
"реализуй валидацию email"

# Хорошо
"напиши validateEmail(). Тест-кейсы: user@example.com → true,
invalid → false, user@.com → false. Запусти тесты после, поправь если упали."
```

Всегда включай тесты, скриншоты или ожидаемый результат.

### 2. Ссылайся на файлы через @

```
# Плохо
"посмотри как работает auth flow в папке auth"

# Хорошо
"посмотри @src/auth/flow.ts и объясни как работает refresh token"
```

### 3. Используй Plan Mode для неопределённости

- Войди в Plan Mode: Shift+Tab (или `/plan`)
- Попроси Claude исследовать и составить план
- Переключись в Normal Mode и выполни план
- Это экономит время на исправление неправильного направления

### 4. Интервью-подход для больших фич

```
1. "Хочу реализовать [краткое описание]. Задай мне подробные вопросы."
2. Claude спрашивает про edge cases, UI, trade-offs
3. Результат сохрани в SPEC.md
4. Начни новую сессию (/clear) и реализуй по спеке
```

### 5. Ограничивай scope и ссылайся на паттерны

```
# Плохо
"добавь виджет календаря"

# Хорошо
"Посмотри как устроен OrderWidget.vue. Сделай CalendarWidget по тому же
паттерну, с выбором месяца и пагинацией по годам. Только существующие библиотеки."
```

### 6. Не исправляй одно и то же больше 2 раз

Если Claude делает ошибку, ты исправляешь, он снова ошибается — `/clear` и перефразируй задачу с учётом того, что узнал. Контекст загрязнён неудачными попытками.

## Управление токенами

### Бюджет контекста: 200K токенов

```
Типичный час работы = 50K–100K токенов
```

### Стратегии экономии (до 30-40% экономии)

1. **Следи за % в терминале.** Выше 80% → завершай и начинай новую сессию.

2. **`/compact` на естественных точках:**
   - После завершения фичи
   - Сжимает решения и код, убирает verbose exploration
   - Освобождает место для следующей задачи

3. **`/clear` между несвязанными задачами.** "Kitchen sink sessions" — главная причина перерасхода.

4. **Используй субагенты для исследования.** Делегируй чтение файлов в subagent, основная сессия остаётся чистой.

5. **Оптимизируй CLAUDE.md:**
   - Указывай конкретные директории для чтения/запрета
   - Доменные знания — в skills (lazy load)
   - Держи < 200 строк
   - "Удаление этой строки приведёт к ошибке?" → Если нет, удали.

6. **Для мелких задач — `/fix`**, не `/feature`. Экономия 3-5x токенов.

7. **Для проверки стиля — `/convention-check`**, не `/review`. Быстрее и дешевле.

## Антипаттерны (чего избегать)

### "Kitchen sink session"
Начал с Task A, спросил про другое, вернулся к Task A. Контекст полон шума.
**Решение:** `/clear` между несвязанными задачами.

### Бесконечное исследование
"Разберись в X" без scope → Claude читает сотни файлов.
**Решение:** Ограничь scope или используй субагенты.

### Перенасыщенный CLAUDE.md
Слишком длинный → Claude игнорирует важные правила (buried в тексте).
**Решение:** Прунь. Тестируй: наблюдай за реальным поведением Claude.

### Доверяй, но проверяй
Код Claude выглядит правильно, но может пропускать edge cases, security, error handling.
**Решение:** Всегда требуй верификацию (тесты, запуск, скриншоты).

### Негативные инструкции
```
# Плохо (Claude активирует концепцию "точка с запятой" прежде чем запретить)
"НЕ используй точку с запятой"

# Хорошо (позитивное утверждение)
"Используй только именованные экспорты"
```

## Effort levels

| Уровень | Когда использовать | Расход |
|---|---|---|
| `low` | Простые правки, известные решения, форматирование | Минимум |
| `medium` | Стандартная разработка (default) | Средний |
| `high` | Сложная логика, архитектура, ревью с Sonnet | Высокий |
| `max` | Глубочайшее reasoning (только Opus) | Максимум |

**Не используй `low` для:** анализа trade-offs, диагностики root cause, генерации новой логики.

## Параллельная работа

Можно запустить несколько сессий Claude Code одновременно:
- Одна для API слоя (Controllers)
- Одна для data слоя (JPA/Repositories)
- Одна для конфигурации/DevOps

Используй `isolation: worktree` в субагентах для безопасной параллельной работы с git.

---

## Java/Spring специфика

1. **CLAUDE.md = универсальные правила.** Доменные знания (JPA, Kafka, конвенция) — в skills.
2. **Skills с `paths: "**/*.java"`** автоактивируются при работе с Java файлами.
3. **Maven hooks** для автокомпиляции после правок.
4. **Для миграций БД** используй агент `migration-reviewer` на Opus — цена ошибки высока.
5. **Тесты обязательны.** Команда `/test` автоматически выбирает правильный уровень (unit vs integration).

## `context: fork` — когда использовать

Запускает skill в изолированном субагенте. Результат возвращается в основную сессию чистым, без промежуточного reasoning.

**Используй для:**
- `/review` — ревью не должно загрязнять контекст реализации
- `/arch` — архитектурный анализ может быть объёмным
- `/convention-check` — чистый список нарушений без мусора

**Не используй для:**
- `/fix` — нужен доступ к текущему контексту
- `/feature` — реализация должна быть в основном контексте
- `/test` — тесты пишутся в основном контексте рядом с кодом

## Полезные команды Claude Code

| Команда | Что делает |
|---|---|
| `/clear` | Полный сброс контекста |
| `/compact` | Сжатие контекста (сохраняет решения, убирает exploration) |
| `/model` | Переключить модель |
| Shift+Tab | Переключение Plan Mode / Normal Mode |
| Ctrl+C | Прервать текущую генерацию |
| `@file.ts` | Явная ссылка на файл (Claude прочитает перед ответом) |
| `!command` | Выполнить shell-команду в сессии |
