# Usage Guide — Практическое руководство

Этот файл — не описание структуры репозитория, а практические советы и примеры для ежедневной работы.

---

## Базовые паттерны

### Как правильно начинать задачу

Для нетривиальных задач (фича, рефакторинг, миграция, интеграция):

```
Прочитай CLAUDE.md этого проекта, затем используй skill java-service-convention.
Задача: [описание задачи]
```

Для быстрых и очевидных изменений (fix опечатки, rename переменной) — просто описывай задачу, без явной загрузки skills.

### Когда явно указывать skill

Указывай skill явно, когда задача выходит за пределы обычного кода:

```
Загрузи skill jpa-db-review и помоги написать индекс для таблицы orders.
```

```
Используй skill docker при написании Dockerfile для этого Go-сервиса.
```

Без явного указания Claude выберет минимально необходимый контекст — это экономит токены.

## Типовые сценарии: Java-сервис

### Новая фича в Spring Boot

```
/feature

Задача: добавить endpoint POST /api/orders/cancel, который отменяет заказ
по его ID. Заказ можно отменить только если его статус PENDING.
```

Команда `feature` проведёт через: анализ контекста → план изменений → реализацию → чеклист проверки.

---

### Code review перед merge

```
/review

Проверь изменения в OrderService.java и OrderRepository.java.
Особенно интересуют: правильность транзакций, обработка ошибок, нет ли N+1.
```

Для глубокого review Java-кода с проверкой конвенций:

```
Выступи в роли java-reviewer.
Проверь изменения в src/main/java/com/example/order/.
```

---

### Миграция БД

```
/plan

Нужно добавить таблицу order_items с внешним ключом на orders.
Используем Oracle. Сервис production, ~500k строк в orders.
```

---

### Kafka consumer или producer

```
Загрузи skill integration-patterns.
Нужно добавить Kafka consumer для топика payment.completed.
Покажи правильную структуру с error handling и logging.
```

---

### Дебаг непонятного бага

```
/fix

Сервис бросает LazyInitializationException в ProductionOrderProcessor.
Stack trace: [вставь trace]
Вот метод, где падает: [код]
```

## Типовые сценарии: Docker

### Написать Dockerfile с нуля

```
Загрузи skill docker.
Нужен Dockerfile для Spring Boot сервиса (Java 21, Maven).
Хочу multi-stage build, финальный образ на eclipse-temurin:21-jre-alpine.
Сервис должен запускаться не от root.
```

---

### Настроить локальное окружение с Docker Compose

```
/plan

Проект: Spring Boot + PostgreSQL + Kafka.
Нужно:
1. docker-compose.yml с инфраструктурой (postgres, kafka)
2. docker-compose.override.yml для запуска app в контейнере с remote debug
3. .env.example с нужными переменными
```

---

### Отладить почему контейнер не стартует

```
Загрузи skill docker (раздел dev-workflow).
Контейнер app стартует и сразу падает. Вот docker compose logs app:
[вставь логи]
```

---

### Оптимизировать размер образа

Загрузи skill docker.

## Управление контекстом

### Когда явно указывать несколько skills

Если задача затрагивает несколько доменов, загружай skills явно:

```
Загрузи skills java-service-convention и integration-patterns.
Нужно добавить Kafka producer в OrderService с правильным logging и error handling.
```

### Когда НЕ нужно загружать skill

- Простые вопросы о коде: "что делает этот метод?"
- Мелкие правки: fix typo, rename переменной
- Общие вопросы о Java/Go синтаксисе

Избыточная загрузка skills тратит токены и шумит.

---

## Чеклист для нетривиальных задач

Перед тем как начать большое изменение:

1. Есть ли локальный `CLAUDE.md` с описанием проекта? Если нет — заполни.
2. Какие skills нужны для задачи?
3. Нужен ли план перед реализацией? → `/plan`
4. Затронуты ли DB, API-контракты, Kafka-топики? → сначала `/plan` (+ агент `migration-reviewer` для схемы)
5. Готов ли тест/проверка перед тем как считать задачу выполненной?

## Частые ошибки

### Слишком короткий промпт

Плохо:
```
Добавь тест
```

Хорошо:
```
Добавь unit-тест для OrderCancellationService.cancel().
Нужно покрыть: успешную отмену, попытку отменить уже отменённый заказ (ожидается OrderAlreadyCancelledException).
```

---

### Просить переписать всё сразу

Плохо:
```
Перепиши OrderService, он выглядит некрасиво
```

Лучше:
```
Найди в OrderService методы, которые нарушают принцип единственной ответственности.
Предложи конкретные выделения, но пока не меняй код — только план.
```

---

### Не указывать контекст стека

Плохо:
```
Как лучше написать этот запрос?
```

Хорошо:
```
Загрузи skill jpa-db-review.
Вот JPQL запрос в OrderRepository. Сервис работает на Oracle, таблица ~2M строк.
Запрос: [код]
```
