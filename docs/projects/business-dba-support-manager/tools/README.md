# Импорт плана в Jira

`jira_import.py` читает [02-plan.md](../02-plan.md) и создаёт в указанном эпике задачи
этапов, их подзадачи, оценки и связи «блокирует». Нужен только Python 3.10+ —
сторонние библиотеки не используются.

## Что создаётся

- **Задача этапа** — на каждый заголовок `# Этап N`. Название:
  `[dba-ops-assistant] Этап N. Название`, описание — «Зачем», «Результат этапа»,
  «Открытые вопросы», «Состав», «Зависимости». Привязывается к эпику (поле Epic Link,
  а если его нет в инстансе — через parent).
- **Подзадача** — на каждый заголовок `### N.M`, включая «Анализ». Название:
  `[Core] 1.1 Каркас: ...`, описание — «Что сделать», «Критерии приёмки», «Открытые
  вопросы». Оценка попадает в Original Estimate, код приложения — в метку (label).
- **Связи** — тип «Blocks»: задача из «Зависимости:» блокирует текущую. Скрипт связей
  не додумывает: зависимость от «Анализа» этапа прописана в плане явно.

Открытые вопросы попадают и в описание подзадачи, где возникли, и в сводку задачи
этапа — так требует план.

Порядок создания: сначала все этапы, потом подзадачи, потом связи — чтобы ссылаться
только на уже существующие ключи.

## Авторизация

Под вашей учётной записью, через personal access token. Токен берётся из переменной
окружения — не из аргументов командной строки, чтобы он не попал в историю команд и в
список процессов.

1. Jira → ваш профиль → **Personal Access Tokens** → создать токен.
2. Задать переменные:

```bash
export JIRA_URL=https://jirasd.o.kg
export JIRA_TOKEN=<ваш personal access token>
```

Если в инстансе токены выключены и нужен basic-режим, дополнительно задайте логин —
тогда `JIRA_TOKEN` используется как пароль:

```bash
export JIRA_USER=<логин>
```

Вместо `export` те же переменные можно записать в файл и передать его через `--env`:

```bash
python3 tools/jira_import.py --epic IT-1234 --env tools/.env
```

Формат файла — строки `KEY=VALUE`; пустые строки и `#`-комментарии игнорируются,
префикс `export` и кавычки вокруг значения допустимы. Переменные, уже заданные в
окружении, файл не перекрывает. Файл `tools/.env` добавлен в `.gitignore`, чтобы
токен не попал в репозиторий — не кладите его в другие каталоги.

## Запуск

Сначала пробный прогон — он ничего не меняет, только печатает дерево задач со связями
и оценками:

```bash
python3 tools/jira_import.py --epic IT-1234 --dry-run
```

Затем создание:

```bash
python3 tools/jira_import.py --epic IT-1234
```

Полезные флаги:

- `--project` — создать задачи не в проекте эпика, а в указанном (например,
  `--project ORSP`): задачи этапов привязываются к эпику полем Epic Link, поэтому
  без этого поля в инстансе чужой проект не сработает — скрипт откажется до создания;
- `--stage` — создать только указанный этап с его подзадачами, можно повторять:
  `--stage 1 --stage 2`; по умолчанию — весь план;
- `--confirm` — спрашивать подтверждение перед созданием каждой задачи:
  `y` — создать, `n` — пропустить, `a` — дальше без вопросов, `q` — остановиться;
- `--file` — другой путь к плану;
- `--task-type` / `--subtask-type` — если типы задач в проекте названы нестандартно
  (по умолчанию определяются автоматически: Task/Задача и Sub-task/Подзадача);
- `--state` — путь к файлу соответствия номеров и ключей.

## Поэтапный импорт

Можно сначала завести только первый этап и посмотреть на результат в Jira:

```bash
python3 tools/jira_import.py --epic IT-1234 --stage 1 --dry-run
python3 tools/jira_import.py --epic IT-1234 --stage 1
```

Остальные этапы доводятся позже обычным запуском без `--stage` — уже созданное не
дублируется, недостающие задачи и связи доздаются. Если подзадача этапа зависит от
ещё не созданной задачи другого этапа, связь при частичном прогоне пропускается с
предупреждением и создастся при следующем запуске, когда обе задачи существуют.

## Повторный запуск

Скрипт ведёт файл `.jira-import-state.json` — соответствие «номер в плане → ключ
задачи». Если прогон оборвался на середине, повторный запуск создаст только
недостающее и не продублирует созданное. Файл локальный, в репозиторий его класть не
нужно. Для импорта в другой эпик или проект укажите другой `--state`.

## Тесты

```bash
cd tools && python3 -m unittest test_jira_import -v
```

Тесты проверяют разбор плана и выбор проекта, в сеть не ходят: количество этапов и
подзадач (9 и 45), поля, зависимости, таймбоксы, наличие «Анализа» лишь у этапов с ADR,
дублирование открытых вопросов в сводку этапа и итоговую сумму оценок (275 часов).
После правки формата плана сначала прогоните их — расхождение форматов вылезет здесь,
а не на половине созданных задач.

## Ограничения

- Скрипт создаёт задачи, но не обновляет уже созданные: если правится текст плана,
  описание в Jira нужно поправить руками или удалить задачи и файл состояния.
- Если в проекте выключен учёт времени, задача создаётся без оценки с предупреждением.
- Тип связи «Blocks» должен существовать в инстансе; в русифицированных инстансах он
  может называться иначе — тогда поправьте имя в `Jira.link`.
