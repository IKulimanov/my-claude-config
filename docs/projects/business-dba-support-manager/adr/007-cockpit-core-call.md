# ADR-007: Способ вызова Core из Cockpit

Дата: 2026-08-10
Статус: принят

## Контекст

Cockpit (`cockpit-dba-ops-assistant`) — бэкенд экранов DBA: вход, сессии, роуты. Своей
бизнес-логики он не содержит и должен вызывать готовые операции движка: списки и карточка
задачи, подтверждение, правка шагов, отклонение, перезапуск, ведение каталогов.

Движок живёт в Core (`business-dba-ops-assistant`) — это отдельный репозиторий, который
собирается и выкладывается независимо. Поэтому вариант «Cockpit собирается из тех же
модулей» недоступен: нужен явный способ вызова между двумя приложениями.

Смежное ограничение: в БД системы пишет только Core — он владелец модели задачи, стадий и
шагов. Любой способ вызова обязан это сохранить, иначе правила целостности задачи
(одна активная стадия, заморозка шагов по статусу) окажутся в двух местах.

## Варианты

1. **Библиотека операций.** Core публикует артефакт с операциями домена, Cockpit
   подключает его зависимостью и работает с БД системы сам.
   - плюсы: нет сетевого слоя и лишней сериализации; одна модель на два приложения;
   - минусы: версии Cockpit и Core обязаны совпадать (общая схема БД), выкладка
     становится связанной; правило «в БД пишет только Core» держится договорённостью,
     а не границей.

2. **Внутренний REST Core для Cockpit.** Core отдаёт операции роутами, Cockpit —
   единственный их потребитель.
   - плюсы: приложения выкладываются независимо; граница владения БД физическая;
   - минусы: контракт нужно версионировать и держать совместимым на версию назад;
     появляется ещё один сетевой отказ, который экраны обязаны показывать внятно.

## Решение

Вариант 2. Cockpit ходит в Core по REST.

Приложения выкладываются независимо — это главное, ради чего Cockpit вынесен в отдельный
репозиторий. Граница владения данными физическая: в БД системы пишет только Core, Cockpit
к ней не подключается.

Аутентификация пользователя — в Cockpit через global-id (вход по учётной записи LDAP); он
владеет сессией и передаёт учётку DBA в вызовы Core. Права на задачу и базу проверяет Core:
правило прав — часть домена и живёт там же, где операции.

Отказ: Core недоступен или контракт разошёлся по версии — Cockpit возвращает экрану внятную
ошибку, экран показывает состояние с возможностью повторить. Контракт «Cockpit -> Core»
версионируется и остаётся совместимым на версию назад — приложения выкладываются порознь.
