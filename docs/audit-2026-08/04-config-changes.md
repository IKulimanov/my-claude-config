## Что НЕ делаем и почему

- **Не трогаем `description` skills, чтобы они «лучше триггерились»** на «проведи анализ». Это тюнинг ради тюнинга
  без способа измерить (автоактивация не логируется). Skills работают через ревьюеров (158 загрузок) — этого достаточно.
- **Не расширяем недельный пайплайн `analytics/`** новыми полями (гипотезы, коррекции). Измерение — раз в месяц
  двумя командами `scripts/audit/*.py` (уже написаны). Добавлять их в launchd — снова инструмент.
- **Не удаляем DevOps-skills** (`docker/helm/kubernetes/terraform/gitlab-ci`): 0 загрузок за окно объясняется
  отсутствием DevOps-задач, а не поломкой; стек рабочий, стоимость хранения ≈ 0.
- **Не удаляем `/convention-check`** (0 вызовов): у тебя по нему незакоммиченная свежая работа (Sonar-чеклист).
  Кандидат на пересмотр через 8 недель вместе с `migration-reviewer` (2 вызова) и `test-writer` (4).
- **Не добавляем Sonar/линтер как MCP или хук** ради 25 промтов «fix this SonarQube» — сначала проверить, не
  закрывает ли это `/convention-check` с Sonar-чеклистом.
- **Не меняем `output-styles/personal.md`, языковую часть `rules/07`, хуки, permissions** — данных о проблемах нет

  анти-слоп для документов (дополнение №5 в `07-docs-and-process.md`, по данным о 4+ промтах «убери ИИ фразы»).
- **Не пишем правило против «как профессионал…»** (46 промтов) — это привычка, не конфиг; идёт в протокол «Рост».
- **`digest-routine.md`** (357 строк, не подключён, не в git): рекомендую удалить — но файл не отслеживается git,

## Диффы (ключевые фрагменты)

### 1a. Новый файл `rules/08-think-first.md` (полностью)

```markdown
# Think First (своя гипотеза до ответа агента)

Зачем: по аудиту `docs/audit-2026-08` отладка и проектирование делегируются первым ходом («вот лог, почему?»,
«предложи вариант»); по данным (RCT Bastani 2025, Shen & Tamkin 2026; мета-анализ Sinha & Kapur 2021) именно
«ответ без своей попытки» разрушает навык, а «попытка → ответ → сверка» его сохраняет.
Действует только для главного агента в диалоге с пользователем (не для субагентов, не для headless `-p`).

## Отладка
Если пользователь просит найти причину ошибки/падения/«не работает» и **не назвал свою гипотезу** — до
исследования задай ОДИН вопрос через AskUserQuestion: «Твоя гипотеза о причине?» с вариантами
«есть гипотеза: …» / «не знаю — ищи» / «срочно — пропусти». Дальше работай как обычно.
В конце ответа одной строкой: `Гипотеза пользователя: совпала | не совпала | не было`.

## Проектирование и выбор решения
Если просят «спроектируй / предложи вариант(ы) / как лучше сделать / напиши план / какой подход» и в промте
**нет своего варианта** — сначала спроси: «Твой первый вариант? (1–3 строки; можно “не знаю”)». В плане
(`docs/shared/plan-template.md`, секция «Каким путём идём») заполни строку «Вариант автора» и скажи, чем
итоговый подход от него отличается. В `/task` вопрос задаётся до запуска подагентов планирования.

## Когда НЕ спрашивать
- гипотеза/вариант уже есть в промте («думаю, что…», «мой вариант…», «скорее всего…»);
- сказано «срочно», «пропусти», «просто сделай», «не знаю» заранее;
- `/review`, `/review-mr`, sonar-замечания, boilerplate, документация, git-операции, follow-up
  «продолжай / следующая фаза»;
- пользователь ответил «не знаю» — не переспрашивать в этой задаче.

Один вопрос, не больше. Гипотезу не оценивать до исследования; после — сравнить честно.
```

### 3. `commands/reflect.md` — шаг «Контекст» и «Шаг 1» (новый текст)

```markdown
**Режим A — та же сессия (основной).** Ты (главный агент) в этой сессии правил файлы через Edit/Write.
Пользователь после этого поправил их руками. Источник «что написал агент» — твои собственные правки в
контексте сессии; источник «что поправил человек» — текущее состояние файлов.

**Режим B — по индексу (старый).** Изменения агента в индексе (`git add`), правки человека — unstaged.

## Шаг 1 — Собрать диффы
Режим A: список файлов, которые ты менял в этой сессии → `git diff -- <file>`, `git diff HEAD -- <file>`,
при коммите пользователя — `git log -n 3 -- <file>` и `git show <коммит> -- <file>`; разница = правки пользователя.
Режим B: `git diff --cached` / `git diff` / `git status`.
Если разницы нет — «правок пользователя не вижу», запиши `reflect: 0 правок` (это данные — «принято без правок»).
Если есть — первая строка ответа: `reflect: N файлов, ~M строк правок пользователя`.
```
