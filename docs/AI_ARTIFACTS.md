# Конвенция артефактов `.ai/`

Идея заимствована из конфигурации Telegram Desktop: держать планы, контекст и ревью каждой задачи
в отдельной директории `.ai/`, которую git игнорирует. Это даёт долговременную «память» о том,
*почему* и *как* делалась фича, переживает компакцию контекста и позволяет вернуться к задаче позже.

У нас принят **лёгкий** вариант по умолчанию. Тяжёлый (многозадачный, с буквами) — опциональное
расширение для команды `/task` на крупных фичах.

## Лёгкий вариант (по умолчанию)

Одна папка на фичу, плоская структура:

```
.ai/<feature>/
  plan.md      # план реализации (то, что раньше жило только в чате)
  review.md    # находки ревью (опционально)
  notes.md     # любые рабочие заметки по фиче (опционально)
```

- `<feature>` — короткое kebab-case имя (например `payment-retry`, `kafka-dlq`).
- Создаётся скриптом `scripts/helpers/ai-init.sh <feature>` — он же добавляет `.ai/` в `.gitignore`
  репозитория ровно один раз. См. `docs/EXTENSION_GUIDE.md`, раздел «Script vs Prompt».
- Файлы — на русском (документация по rule 07). Идентификаторы и пути — английские.
- Нет обязательного `about.md`, нет подпапок-букв, нет `logs/`. Минимум церемонии.

## Тяжёлый вариант (опционально, для `/task`)

Для крупных фич, которые не помещаются в один контекст и идут несколькими последовательными
задачами. Используется только командой `/task`:

```
.ai/<project>/
  about.md            # вневременной «слепок» проекта, переписывается на каждой задаче
  a/                  # первая задача
    context.md        # самодостаточный контекст задачи (его читают подагенты вместо чата)
    plan.md
    review1.md        # до 3 итераций ревью
    logs/             # prompt/progress/result делегированных фаз
  b/                  # следующая задача
    ...
```

- `about.md` описывает проект так, будто всё уже готово — без «TODO», «текущее состояние»,
  «пока не сделано». Переписывается (не дополняется) в начале каждой новой задачи.
- `context.md` самодостаточен: подагент с нулевым контекстом должен понять задачу, читая только его.
- Буквы `a`, `b`, `c`, … — последовательные задачи внутри одной фичи.
- Создаётся `ai-init.sh <project> <letter>`.

## Где это используется

| Команда | Что пишет в `.ai/` |
|---|---|
| `/feature` | `plan.md` фичи (лёгкий вариант) |
| `/plan` | `plan.md` |
| `/review` | `review.md` |
| `/review-mr` | копию ревью (основной файл по-прежнему уходит в `~/docs/work/reviews/...`) |
| `/task` | тяжёлый вариант: `about.md`, `<letter>/{context,plan,review}.md`, `logs/` |

## Почему git игнорирует `.ai/`

Это локальные рабочие артефакты конкретного инженера, а не часть истории проекта. Их не коммитят,
чтобы не засорять репозиторий и не навязывать команде формат. `ai-init.sh` добавляет строку `.ai/`
в `.gitignore` репозитория при первом запуске.
