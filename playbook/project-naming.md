# Стандарт нейминга микросервисов

Этот стандарт помогает единообразно именовать микросервисы и определять их принадлежность к конкретной доменной области и функциональности.

---

## Формат названий

`[префикс]-[доменная область]-[функциональность]`

**Префикс** может принимать одно из четырёх значений:

1. **business** — сервисы с бизнес-логикой.
2. **integration** — сервисы для интеграции с внешними системами.
3. **cockpit** — админ-панели и инструменты управления.
4. **mediation** — сервисы для сбора, преобразования и маршрутизации данных.

**Доменная область** — более крупная тема, к которой относится сервис.

**Функциональность** — конкретная роль сервиса (например, `dispatcher`, `sender`, `api`, `dashboard`, `manager`, `collector`, `transformer` и т.д.).

Пример:

`business-notification-dispatcher`

Здесь:
- **business** — сервис с бизнес-логикой,
- **notification** — доменная область (уведомления),
- **dispatcher** — функциональность (распределение уведомлений).

---

## Детали по типам сервисов

### 1. Business

`business-[доменная область]-[функциональность]`

Содержат основную бизнес-логику: расчёты, правила, валидацию.

**Примеры:**
- `business-notification-dispatcher`
- `business-operator-detailing`

### 2. Integration

`integration-[доменная область]-[функциональность]`

Взаимодействие с внешними системами.

**Примеры:**
- `integration-myo-sms-sender`
- `integration-redknee-api`

### 3. Cockpit

`cockpit-[доменная область]-[функциональность]`

Админ-панели и инструменты управления.

**Примеры:**
- `cockpit-notification-system`

### 4. Mediation

`mediation-[доменная область]-[функциональность]`

Сервисы для сбора, преобразования и маршрутизации данных.

**Примеры:**
- `mediation-trigger-platform`

---

## Рекомендации

1. **Используйте дефисы** для разделения частей имени.
2. **Избегайте общих слов** вроде `system` или `service`, если они не несут смысла.
3. **Уточняйте функциональность** (manager, collector, admin, api и т. д.).
4. **Поддерживайте единообразие**: если уже есть `cockpit-billing-admin`, то для другого админ-сервиса сохраняйте такой же паттерн.
5. **Не перегружайте** название: достаточно трёх частей (`префикс-домен-функциональность`).
