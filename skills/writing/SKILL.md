# Умение: текст для человека

Символы и язык - правило 07, раздел "Любой текст". Здесь - как устроить документ, чтобы его прочли один раз и поняли.
Паттерны воды с примерами - `references/slop-patterns.md`. HTML-отчёт - `references/html-report.md`.

## До первой строки

Ответь себе тремя строками, в документ они не идут:

- Кто читает и что он уже знает. Автор задачи знает контекст, коллега через полгода - нет.
- Что читатель сделает после чтения: примет решение, выполнит шаги, найдёт значение, поймёт причину.
- Главный вывод одним предложением. Не получается - материала ещё нет, писать рано.

## Тип документа

Один документ - один тип. Смешанные режут на части или ссылаются друг на друга.

| Тип | Вопрос читателя | Обязательно | Лишнее |
|---|---|---|---|
| Инструкция | Как сделать X? | Условия до начала, шаги по порядку с командами, как проверить результат | Объяснение устройства, варианты |
| Справочник | Какое значение у Y? | Полнота, один формат записи, таблицы, значения по умолчанию | Рассуждения, история |
| Объяснение | Почему так устроено? | Проблема, механизм, компромиссы, схема | Пошаговые команды |
| Решение (ADR, план) | Что выбрали и чем платим? | Варианты, выбор, причина, последствия, что не делаем | Пересказ контекста в каждом разделе |
| Отчёт (анализ, статистика, summary) | Что вышло и что делать? | Вывод, числа с источником, что проверить, открытые вопросы | Хроника работы |

## Порядок

- Вывод первым: итог, решение или ответ в первых трёх строках. Дальше - от важного к подробностям.
- Заголовок говорит содержание, а не тему: "Хук проверяет только добавленный текст", а не "О хуке".
- Один абзац - одна мысль, первое предложение её называет.
- Второстепенное (журнал, полные логи, отклонённые варианты, длинные таблицы) - в `<details>` с содержательным
  `<summary>`: "Отклонённые варианты (3)", а не "Подробнее".
- Числа - с единицей и источником: "21,5 КБ (`wc -c rules/*.md`)", а не "заметно выросло".

## Форма

| Содержание | Форма |
|---|---|
| Причина, связь, оговорка | Проза, 2-4 предложения |
| Шаги по порядку | Нумерованный список |
| То, что нужно сделать или проверить | Список с галочками `- [ ]`, по одному действию в строке |
| Сравнение по двум и более признакам | Таблица |
| Поток, зависимости, состояния | Схема: mermaid в md, SVG в html, до 7 блоков, стрелки подписаны |
| Числа во времени или доли | График в html, таблица в md |
| Команда, путь, идентификатор | `inline code` или блок кода |

Список из двух пунктов - это предложение. Таблица из одного столбца - это список. Жирный - только для термина при
первом определении, не для украшения.

## Markdown или HTML

- Markdown: документ правят руками или скриптами, смотрят в diff, он короче 100 строк, это README, ADR, задача,
  `plan.md`, `tests.md`, `summary.md`.
- HTML: документ читают, а не правят, и в нём есть схема, график или больше трёх таблиц. Анализ, исследование,
  статистика, аудит, обзор дизайна, сравнение вариантов. Правила и шаблон - `references/html-report.md`.
- HTML стоит в 2-4 раза больше токенов. Для ответа на один вопрос он не нужен.

## Предложение

- Подлежащее - тот, кто действует: "хук читает `new_string`", а не "осуществляется чтение".
- Глагол вместо отглагольного существительного: "проверяет", а не "выполняет проверку".
- Одно предложение - одно утверждение. Длиннее 25 слов - разрезать.
- Один термин на одно понятие во всём документе.
- Оговорка только там, где есть сомнение, и с причиной: "не проверял на Windows".

## Второй проход

После черновика перечитай как читатель из первого раздела и исправь:

- [ ] первые три строки отвечают на вопрос читателя;
- [ ] нет предложения, которое можно удалить без потери смысла;
- [ ] нет паттернов из `references/slop-patterns.md`: вступление, пересказ, "не X, а Y", тройки ради ритма, итог-повтор;
- [ ] имена, пути, числа конкретные; у чисел есть источник;
- [ ] действия оформлены галочками, второстепенное свёрнуто;
- [ ] только символы с клавиатуры (правило 07);
- [ ] команды и пути проверены: существуют и выполняются.

## Чего не делать

Не писать о самом документе ("в этом разделе рассмотрим"). Не объяснять читателю то, что он знает. Не добавлять
разделы "Введение", "Заключение", "Итог". Не оценивать текст баллами. Не сокращать до телеграфного стиля: предлоги
и связки остаются.
